================================================================================
EXTENSION: ADDING NEW DATA SOURCES
================================================================================

To add Observation.org (or any source):

1. Get API key: https://www.observation.org/api/v2

2. Update the adapter (in next_dutch_firsts_source_adapters.py):
   def fetch(self):
       response = requests.get(
           f"{self.api_base}/observations",
           params={"since": (datetime.now() - timedelta(days=7)).isoformat()},
           headers={"Authorization": f"Bearer {self.api_key}"},
       )
       return response.json()

3. Register with manager:
   from src.next_dutch_firsts_source_adapters import ObservationOrgAdapter
   ebird = ObservationOrgAdapter(api_key=os.getenv("OBSERVATION_ORG_API_KEY"))
   manager.register_source(ebird)

4. Run update:
   manager.update_all_sources()

That's it! No changes to core scoring or dashboard code needed.

================================================================================
ARCHITECTURAL HIGHLIGHTS
================================================================================

Design Patterns Used
────────────────────

✓ Source Adapter Pattern
  • Each source implements uniform interface (fetch, validate, transform, load)
  • New sources added without modifying core code
  • Dependency injection via manager.register_source()

✓ Priority Fallback Strategy
  • Live Data (P1) > Historical (P2) > Manual (P3)
  • Allows graceful degradation if live sources unavailable
  • Maintains data consistency across tiers

✓ Factory Pattern
  • create_live_data_manager() encapsulates initialization
  • Default sources pre-registered automatically
  • Custom sources added via API

✓ Registry Pattern
  • SourceRegistry tracks all sources centrally
  • Metadata persisted (last_updated, status, record_count, error)
  • Dashboard pulls from registry for status view

✓ Data Quality Tracking
  • Every record tagged with quality tier (verified/provisional/unverified)
  • Confidence scores (0-1) enable weighted decision-making
  • Source attribution metadata for transparency

Data Storage Decisions
──────────────────────

✓ Parquet Format
  • Columnar storage (efficient for analysis)
  • Compressed (~50% vs CSV)
  • Native Pandas support (.read_parquet())
  • Schema validation on read
  • Partitionable for large datasets

✓ CSV Metadata Registry
  • Human-readable source status
  • Easy to audit and version control
  • Appendable (no schema locks)
  • Compatible with Excel, spreadsheets

✓ JSON Status Cache
  • Fast dashboard updates (no re-computation)
  • Lightweight (<1 KB)
  • Automatic refresh on each update cycle
